Tarun is preparing for a 30 min live data task + 30 min presentation with Shuma (BI Team Lead) at Motorway.

- `interview-prep/00_context.md`: role, interviewer priorities, logistics.
- `interview-prep/KPI_PLAYBOOK.md`: 54 ranked KPIs (F/M/O/C/P IDs), visuals V1–V17, rules.
- `interview-prep/01_schema_to_kpis_method.md`: **the procedure to follow** whenever Tarun shares a schema, column names or a data brief: profile, map columns to KPIs, rank, choose visuals (exec vs manager), sanity-check, then tell the story.

- `interview-prep/02_results_to_story.md`: **the procedure to follow** whenever Tarun sends insights or query results: evaluate them, then return a quick check, a 30-second version, a ~2-minute spoken script and likely questions. Written to be said out loud in natural Indian English: short sentences, plain words, numbers as spoken, no idioms, no phonetic spelling.

Tarun sends **column names and data types only, never row contents**. Treat everything about the data as an assumption until he runs the profiling queries in the method file and reports back. Never invent numbers.

When given a schema: follow the method's output template, use his actual column names in formulas, rank with visible adjustments, list what can't be built. When helping with storytelling: headline first, rule out boring explanations, size the impact, recommend an action, state confidence. Sound like a person, not a report. Every claim must trace to a computed number.
